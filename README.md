# Birdwatcher

Watches the course materials of CS 212, AI Programming 1 at Lane Community College, for consistency problems and blind spots.

Joshua Evans, 2026-11-10 (written with Claude Opus 5.5)

## What it does

Birdwatcher downloads Brian Bird's public course repository, [lcc-cit/CS212-CourseMaterials](https://github.com/lcc-cit/CS212-CourseMaterials), runs static checks over it, and reports each problem it finds with a link to the exact file and line.

The course repository already checks that its links resolve, using [lychee](https://lychee.cli.rs/) in GitHub Actions. Birdwatcher looks for what a link checker can't see: links to sections that don't exist, files left over from renumbering, accessibility problems, and code that breaks the course's own style rules.

**Status:** early development, as the CS 212 Lab 6 project. It grows into the term project: Lab 7 adds analysis by a large language model, and the term project adds simulated students. Downloading and caching work; the checks and reports below are being built.

## Setup

Requires [uv](https://docs.astral.sh/uv/), which installs Python 3.12 itself.

```powershell
uv sync
uv run pytest
```

## How it works

### Downloading and caching

Each run asks GitHub for the latest commit on the course repository's `main` branch. If the local cache already holds that commit, the cached copy is used and nothing is downloaded. Otherwise the zip archive of exactly that commit is downloaded and replaces the cached copy.

- Without a network connection, the cached copy is used and reported as possibly out of date.
- Every path in the archive is checked before anything is extracted, so an archive cannot write outside the cache.
- An interrupted download never leaves a partial copy that a later run would trust.

### Findings and reports

Checks produce findings as plain data: the check, the severity, the file and line, and a message. Separate renderers turn findings into output:

- **Console:** colored, grouped by file, with clickable links (the default).
- **HTML report:** a self-contained folder that opens from disk, like a test coverage report.

Each finding links to its source line on GitHub, at the commit that was checked, so the link stays correct after the file changes.

Findings also link to their place in the HTML report. Windows drops the `#section` part of `file://` links opened from a terminal or by Python's `webbrowser`, so the report includes a small redirect page per finding (`report/go/<finding>.html`) that jumps to the right section inside the browser.

## Checks

- [x] **Broken section links:** links to a `#section` that doesn't exist on the target page. Section ids follow the site generator's rules, which turn "Architect & Planner" into `architect--planner`; tables of contents generated by other tools often expect `architect-planner`.
- [ ] **Renumbering leftovers:** files whose name gives a different lab number than the lab folder they are in.
- [ ] **Stray language labels:** a line reading only "Python" directly above a code block, left over from pasting code in an editor.
- [ ] **Skipped heading levels:** a heading more than one level below the previous one, which breaks navigation for screen-reader users.
- [ ] **Images without alt text:** images that screen readers cannot describe.
- [ ] **Incomplete front matter:** pages missing a `title`, `description` or `author`.
- [ ] **Python style:** [Ruff](https://docs.astral.sh/ruff/) over the course's `.py` files, using the rules from the course's own `PythonStyleAndBestPracticesChecklist.md`.

### Ideas for later

- Python code blocks that don't parse, ignoring `>>>` prompts and deliberate placeholders such as `???`.
- Lab self-numbering: page titles and main headings that name a different lab than their folder.
- Lab completeness: every lab has its instructions, code review form and rubric, and none of them only as a draft.
- License notices on pages that agree with each other and with the repository's `LICENSE` file.
- Analysis of the materials by a large language model (Lab 7).
- Simulated students who attempt a lab using only the published materials (term project).

## Development

| Command | Does |
|---|---|
| `uv run pytest` | Runs the tests. Tests sit next to their module, named `*_test.py`. |
| `uv run ruff check` | Lints with the course style rules (configured in `pyproject.toml`). |
| `uv run ruff format` | Formats the code. |
